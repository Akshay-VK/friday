# Domain docs

## Layout and reading rules

This repo uses a single-context layout:
- `GLOSSARY.md` at the repository root.
- `docs/adr/` for architecture decision records.

Before exploring, read the glossary and ADRs relevant to the work.
If absent, proceed silently; domain-modeling creates them lazily when
terms or decisions are resolved.

## Vocabulary

Use glossary-defined terms in issues, proposals, hypotheses, and tests.
When a needed concept is missing, reconsider the terminology or note
the gap for domain-modeling.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR, identifying
the ADR and explaining why the decision may need reopening.
