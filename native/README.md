# Windows local scan-root metadata helper

`source-preview.c` is source-reviewed Windows-only code. On WSL/Linux with an already available MinGW cross compiler, run `npm run build:native:windows`. This generates `native/source-preview.exe` **locally**; the executable is ignored by Git, is not downloaded or included in `npm ci`, and no compiler or Windows system component is installed automatically. Rebuild after updating the C source. Copy the reviewed executable alongside `native/source-preview.c` when preparing a Windows host checkout. Windows source preview **fails closed** if it is absent or cannot validate a local root; other platform development does not require it.

The helper accepts `--preview <drive-absolute-root> <drive-absolute-data-home>` or `--identity` with the same two arguments. It opens the root, data home and path ancestors without write/delete rights, refuses reparse/uncertain cloud metadata and aliases, holds handles without delete sharing while validating, and enumerates only the open root handle. It never opens a child by its name or reads file contents. Output is a single ASCII-escaped, versioned JSON object validated by the server; stderr is diagnostic only. The server bounds output, kills the child after five seconds or on cancellation, and checks root volume/file ID and the permission generation again at approval. The helper does not provide a recursive walker or guarantee against arbitrary volume mapping changes, other processes changing child metadata, or future access after the handle is closed.

Run `node.exe --test test/native-source.test.ts` from a Windows checkout with separately installed Windows Node dependencies and the locally built helper. `node.exe --test test/browser.test.ts` uses an already installed headless browser (no installation). The folder picker is separate: manual path entry works without it; an interactive picker selection has not been verified by these headless tests. Cloud-provider nonhydration needs a separately authorized genuine provider fixture and monitor; synthetic flags alone do not prove it. WSL roots remain unsupported pending explicit distro/user mapping verification.

`source-inventory.c` is a separate bounded Windows-only child reader for approved ordinary local roots. Build with `npm run build:native:inventory`; run `node.exe test/native-inventory.cjs` and `node.exe --test test/native-source.test.ts` with native Windows dependencies. Its public app route requires an active persisted grant and matching root file ID, without a diagnostics/TEMP-name restriction. Unambiguous top-level exclusions are passed to the native helper; unsupported exclusions fail closed. Shares, WSL, aliases and uncertain cloud roots remain refused. Child opens use `FILE_FLAG_OPEN_NO_RECALL | FILE_FLAG_OPEN_REPARSE_POINT`, no-delete ancestor handles and pre-read attributes/file-ID checks; failed listed-child opens are marked partial. Caps: 32 entries, depth 3, 256 file bytes, 8192 serialized bytes and one helper with server-side 2.5-second kill/wait timeout. Only successful exit with a complete `END` commits. Cached reads revalidate root identity; derived inventory is removed on disable/revoke and excluded from backup. This is **not** a production project detector or proof of genuine cloud-provider nonhydration/native attempted-write absence (#57).

Win32 boundary references: [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex), [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew), [cloud placeholder classification](https://learn.microsoft.com/en-us/windows/win32/api/cfapi/nf-cfapi-cfgetplaceholderstatefromattributetag).
